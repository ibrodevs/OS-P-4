## Цель работы

Сравнить потоки и процессы в Python на CPU-bound и I/O-bound задачах, понять влияние GIL и показать различие между общей памятью потоков и изолированной памятью процессов.

## Что реализовано

- `cpu_benchmark.py` сравнивает последовательное выполнение, 4 потока и 4 процесса при суммировании чисел;
- `generate_numbers.py` создаёт большой тестовый файл для честного CPU-бенчмарка;
- `network_benchmark.py` сравнивает последовательную загрузку, `ThreadPoolExecutor` и `ProcessPoolExecutor` для 20 URL;
- `memory_demo.py` показывает, что потоки видят одну глобальную память, а процессы — отдельные адресные пространства.

## Запуск

```bash
python3 generate_numbers.py --count 2000000
python3 cpu_benchmark.py
python3 network_benchmark.py
python3 memory_demo.py
```

## Ключевая идея

Для **CPU-bound** Python-кода потоки обычно не ускоряют вычисление из-за GIL: Python-байткод в одном процессе исполняется одним потоком за раз. Несколько процессов имеют отдельные интерпретаторы и отдельные GIL, поэтому могут использовать несколько ядер.

Для **I/O-bound** задач потоки эффективны: пока один поток ждёт сеть или диск, другие могут выполнять работу. Процессы здесь тоже возможны, но обычно имеют лишние накладные расходы.

## Вывод

Потоки подходят прежде всего для конкурентного I/O и используют общую память. Процессы лучше подходят для параллельных CPU-вычислений и имеют изолированную память, но стоят дороже по созданию и обмену данными.
